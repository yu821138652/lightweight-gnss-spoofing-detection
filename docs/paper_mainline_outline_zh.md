# 论文主线大纲：消费级异构 GNSS 终端的场景感知式欺骗检测与关联异常协同诊断

> 本文档用于统一论文写作主线、实验组织和结果表述。它不是最终论文正文，后续应随着协议锁定和新实验结果更新。
>
> 当前主线的核心不是继续追求“逐卫星二分类准确率”，而是解释消费级异构设备上的跨频段、跨设备响应差异，并构建能够同时输出“攻击场景”和“设备响应状态”的轻量化诊断系统。

## 1. 论文定位

### 1.1 建议题目

**消费级异构 GNSS 终端的场景感知式欺骗检测与关联异常协同诊断方法**

英文题目可暂定为：

**Scene-Aware Spoofing Detection and Correlated-Anomaly Diagnosis for Heterogeneous Consumer GNSS Devices**

### 1.2 一句话主线

消费级 GNSS 芯片和设备具有明显异构性，目标频段的直接欺骗还可能诱发非目标频段的设备关联异常；因此，本文采用“频段场景识别 + 设备响应状态识别 + 多设备后融合”的双层诊断框架，分别回答“发生了什么攻击场景”和“每台设备出现了什么响应”。

### 1.3 论文要解决的问题

现有逐卫星、单一二分类方法在真实消费级设备上容易受到以下因素影响：

1. 不同芯片对 C/N0、AGC、缺失值和卫星可见性的响应不同，设备相关特征容易成为模型捷径。
2. L5 欺骗时，真正直接受影响的 L5 信号数量可能较少；数量更多的 L1 信号可能表现为压制、丢星或 C/N0 下降，导致模型学到“L1 异常负类”而不是 L5 直接欺骗。
3. 没有 L5 能力的设备无法被判定为“L5 direct”，但它们仍可能在 L5 攻击期间出现可重复的 L1 关联异常。
4. 因此，“设备处于攻击/异常事件中”和“某个信号是否被直接欺骗”不是同一个预测任务，必须分层建模。

## 2. 摘要写作骨架

摘要建议按以下五句话组织：

1. **背景与问题**：消费级 GNSS 设备异构性和多频段耦合使传统逐卫星检测跨设备泛化困难。
2. **关键发现**：绝对 AGC 等硬件相关特征可能在单设备内有效、跨设备时失效；L5 欺骗期间部分设备会出现非目标 L1 的下降型关联异常。
3. **方法**：提出频段聚合的场景分支、三状态设备响应分支和多设备后融合框架。
4. **结果**：报告场景分类、异常发现、直接欺骗识别和联合诊断四类指标，并重点说明 Huawei/RedMi 的 L5 漏检和误报得到明显缓解。
5. **意义与边界**：方法面向广播式、多星同频的频段级欺骗；对单星或选择性 PRN 欺骗不能替代卫星级定位。

摘要中不要把开发性 outer-test 结果写成未经使用的独立盲测结果；最终数值应以协议锁定后的正式汇总表为准。

## 3. 引言结构

### 3.1 研究背景

- GNSS 欺骗会改变接收机的载噪比、跟踪状态和伪距相关观测。
- 手机、手表等消费级终端具有低成本、数量多、可众包部署的优势，但芯片、天线、固件和可输出字段差异显著。
- 轻量化检测不能只依赖实验室接收机中稳定可得的专用观测量。

### 3.2 现实痛点

- 同一攻击场景在不同设备上的 C/N0、AGC 和可见卫星数变化方向可能不同。
- 传统 target-band-only 逐卫星二分类无法表达“直接欺骗”和“攻击关联异常”的区别。
- L5 观测数量少、无 L5 设备普遍存在，直接把所有异常归入 L5 direct 会产生错误语义。

### 3.3 本文的两个核心发现

**发现一：设备专属特征的跨设备泛化副作用。**

AGC、SvTimeUnc 等特征可能在训练设备内提供很强的判别力，但在不同芯片、缺失 AGC 或 AGC 退化时会成为“毒特征”。本项目中，去除 AGC 后场景分支的跨录制表现显著改善，RedMi K60 的攻击召回从含 AGC 时的低水平提升到接近完全检出，Huawei 的误报/漏检也明显缓解。

**发现二：L5 欺骗下的非目标 L1 关联异常。**

在部分设备上，L5 受到欺骗时 L5 C/N0 上升，而未直接受骗的 L1 可能出现 C/N0 下降、信号稀疏或跟踪受压制。两个 Pixel Watch 没有 L5，Watch1 还没有 AGC，但其 L1 仍出现明显变化，说明该现象不能简单解释为 L5 直接观测缺失。

论文应将“捕获、跟踪或共享接收机资源导致的跨频段耦合”作为待验证的可能机理，不要在没有芯片级证据时断言唯一因果链。

### 3.4 研究空白

现有工作通常分别关注：

- AGC、C/N0 或相关函数等单类观测量；
- 单设备或同构接收机；
- 目标频段的直接欺骗；
- 卫星级检测或位置一致性检查。

针对消费级异构设备中“场景级攻击 + 设备级关联响应”的协同诊断仍缺少统一、轻量且可解释的框架。

### 3.5 贡献点

建议最终凝练为四点：

1. **问题建模贡献**：将消费级 GNSS 欺骗诊断拆分为频段场景识别、设备响应状态识别和联合诊断三个层次，区分 direct spoof 与 attack-associated anomaly。
2. **经验发现贡献**：通过跨设备消融实验揭示 AGC 等硬件相关特征的泛化副作用，并系统记录 L5 欺骗下非目标 L1 关联异常现象。
3. **方法贡献**：提出不依赖设备专属 AGC 的频段聚合场景分支、三状态设备响应分支和直接欺骗专家校准机制。
4. **系统与验证贡献**：通过多设备场景后融合输出可解释诊断结果，在低误报约束下同时评估异常发现、直接欺骗识别和联合召回，并分析适用边界。

## 4. 相关工作组织

相关工作建议分成五组，而不是按单篇论文罗列：

1. **GNSS 欺骗检测综述与攻击分类**：建立传统信号级、接收机级和位置一致性检测背景。
2. **AGC/C/N0 及接收机观测量检测**：说明 AGC 是经典观测量，同时引出其设备依赖性。
3. **消费级 Android/智能设备 GNSS 观测质量**：支撑芯片、设备、频段可用性和缺失字段的异构性。
4. **双频 GNSS 的 L1/L5 捕获、跟踪和辅助关系**：为跨频段关联异常提供机理讨论依据，但只写成可能解释。
5. **部分卫星欺骗与多接收机/多设备协同检测**：用于界定本文频段级方法与卫星级精细定位方法的关系。

参考文献清单和检索方向见本文档末尾的“文献准备”。

## 5. 数据、标签与任务定义

### 5.1 数据对象

- 数据来源：手机、手表等真实消费级 GNSS 设备。
- 研究单位：完整录制 Session，而不是独立 signal endpoint。
- 当前正式数据快照：123 份原始日志；纯静态路线包含 7 个 reviewed 静态录制，统一静态+动态路线包含静态和动态完整 Session。
- 所有正式切分以完整 Session/outer group 隔离，避免同一采集事件跨 train、validation 和 test。

### 5.2 三类标签语义

#### 信号/卫星级

目标是判断某个 `signal_id` 是否被目标频段直接欺骗。当前 target-band-only 标签保持不变；L5 攻击期间 L1 的下降不自动改成 L1 direct。

#### 设备响应级

设备窗口输出三状态：

| 状态 | 含义 |
|---|---|
| `normal` | 正常或没有可观测攻击相关响应 |
| `anomaly` | 攻击相关但非直接欺骗的异常响应，例如 L5 攻击期间 Watch 的 L1 压制 |
| `direct` | 设备在目标频段存在直接受骗证据 |

设备响应标签不修改中央 CSV，也不反向改写信号级直接欺骗标签。

#### 场景级

场景分支输出：

```text
normal / L1 / L5 / L1+L5
```

该输出表示当前窗口的频段攻击场景，不表示每颗卫星都被直接欺骗。

### 5.3 联合诊断目标

最终系统输出：

```text
攻击场景 + 每台设备的响应状态 + 可选的直接受骗信号证据
```

例如，在 `L5` 场景下，某个没有 L5 的 Watch 应输出 `L5 + anomaly`，而不是强行输出 `L5 + direct`。

## 6. 方法章节结构

### 6.1 总体框架

```text
原始 GNSS Raw measurements
        │
        ├── 频段聚合场景分支 ──> normal/L1/L5/L1+L5
        │                              │
        └── 设备响应分支 ───────> normal/anomaly/direct
                                       │
             同一 TOW 的多设备场景后验平均与共识
                                       │
                          联合诊断结果与解释性输出
```

两个分支分别学习“攻击是什么”和“设备怎样响应”，不把两个任务强行压成一个标签。

### 6.2 频段场景分支

**判别单元**：设备在当前窗口末端历元的频段场景。

**特征**：每个历元分别聚合 L1/L5 的 C/N0、接收机时间不确定度、伪距率不确定度，并保留 L1/L5 presence。当前融合实验采用去 AGC 的 8 维版本；C/N0-only 4 维版本作为更强的跨设备候选，需要在完全相同的六/七折融合协议下公平复验。

**窗口**：连续 5 个历元，严格因果，不跨 split、segment 或长时间断档。

**模型**：轻量 TCN。两层因果卷积，末端 embedding 接四分类头；使用反频率类别加权 CrossEntropy 和 AdamW。

**关键设计理由**：

- 直接在窗口级同时看到 L1 和 L5，能够区分 L5-only 与 L1+L5；
- 频段聚合减少卫星数量和设备卫星可见性差异带来的噪声；
- 去除绝对 AGC，避免模型依赖硬件特定捷径。

### 6.3 设备响应状态分支

**判别单元**：一个设备在一个时间窗口内的响应状态。

**输入**：L1/L5 设备级聚合、稀疏极值、可观测率、设备信息、初始正常基线差分，以及显式的 L5-L1 差异和“L5 上升 + L1 下降”耦合特征。

**基线**：三分类 MLP，输出 `normal/anomaly/direct`。

**直接欺骗专家**：另训 `non-direct/direct` 二分类专家，在 validation 上按 FAR 和 abnormal recall 约束校准阈值，再对 base model 进行 direct 覆盖。阈值按折独立确定，不能固定手调或读取 outer test 后选择。

**为什么保留三状态**：设备没有 L5 不等于设备正常；设备出现 L1 下降也不等于 L1 被直接欺骗。三状态使这两类事实可以同时表达。

### 6.4 多设备后融合

1. 对同一 TOW 的多台设备场景后验做平均。
2. 形成场景共识，并把共识场景附加给每台设备。
3. 保留每台设备自己的 `normal/anomaly/direct` 响应状态。
4. 不因为场景是 L5 就把无 L5 设备强制改为 `L5 direct`。

后融合不重新训练一个统一大模型，便于解释每个分支的作用，也便于处理不同设备的缺失频段。

## 7. 实验设计

### 7.1 对比路线

论文建议按以下顺序组织实验，而不是只展示最终融合结果：

1. 原始逐 signal 二分类基线：说明 L5、Huawei、RedMi 和跨设备泛化问题。
2. 特征消融：完整特征、去 AGC、C/N0-only。
3. 频段场景分支：验证频段聚合能否识别 `normal/L1/L5/L1+L5`。
4. 设备响应分支：验证只做 abnormal 检出，以及进一步区分 anomaly/direct 的代价。
5. 后融合系统：验证场景上下文是否能在保持设备状态语义的同时提高联合诊断可靠性。
6. 动态场景扩展：单独报告 static、dynamic 和 `dy_L5`，不与纯静态结果直接排序。

### 7.2 评估协议

- 纯静态：7-fold outer-session / inner-time-block 协议；响应状态当前已有 6 个有效 fold，另有一个 fold 因 outer test 从攻击中段开始而无法建立 30 窗口初始正常基线，需要单独处理。
- 静态+动态：统一的 mixed outer-CV；完整采集事件绑定为 outer group。
- scaler、初始基线和阈值只使用训练/validation；outer test 仅在模型与策略锁定后读取。
- 已经读取并用于诊断的 test 结果只能作为开发性证据，不能包装为新的独立盲测。

### 7.3 指标口径

#### 场景分支

- Macro-F1、Accuracy；
- `normal`、`L1`、`L5`、`L1+L5` 各类 recall；
- 跨设备、跨 Session 的 recall/FAR。

#### 设备响应分支

- `abnormal recall`：真实 `anomaly` 或 `direct` 中被判为非 `normal` 的比例；
- `anomaly recall`：真实关联异常被正确判为 `anomaly` 的比例；
- `direct recall`：真实直接欺骗被正确判为 `direct` 的比例；
- FAR：正常窗口被误报为异常的比例；
- supported Macro-F1：只对 test 中实际存在的类别计算，另报告原始 Macro-F1 和类别 support。

#### 联合系统

- 场景正确且设备状态正确的 `joint recall`；
- `anomaly joint recall` 与 `direct joint recall`；
- 场景上下文覆盖率；
- 每设备 Recall、最差设备 Recall、每 Session 波动和检测时延。

不同任务的 recall 不应直接互相排序：abnormal recall、anomaly recall、direct recall 和 joint recall 的分母不同。

## 8. 当前结果在论文中的摆放方式

下面的数字是当前已完成的开发性汇总，最终论文表格应在协议和 checkpoint 冻结后重新导出。

### 8.1 特征消融：解释跨设备泛化问题

| 场景分支版本 | 跨录制 Macro-F1 | L1 recall | L5 recall | L1+L5 recall |
|---|---:|---:|---:|---:|
| 完整 10 维（含 AGC） | 0.728 | 0.475 | 0.813 | 0.449 |
| 去 AGC 8 维 | 0.948 | 0.713 | 0.984 | 0.987 |
| C/N0-only 4 维 | 约 0.992 | 0.985 | 0.982 | 0.988 |

C/N0-only 结果必须在和最终融合完全相同的协议下复验后，才能作为主模型结果；当前最稳妥的写法是把“去 AGC 显著改善”作为已确认结论，把 4 维版本作为强候选。

### 8.2 Huawei/RedMi L5 问题闭环

| 设备 | 含 AGC recall | 去 AGC recall |
|---|---:|---:|
| RedMi K60 | 0.228 | 0.996 |
| HUAWEI Mate40 | 0.667 | 0.881 |

这张表应放在“跨设备泛化与特征消融”小节中，明确说明它直接回应了原始的 L5 漏检和设备误报问题。

### 8.3 静态设备响应状态

当前 6 个有效 fold 汇总：

| 指标 | 结果 |
|---|---:|
| Macro-F1 | 0.8946 |
| FAR | 1.17% |
| abnormal recall | 93.95% |
| anomaly recall | 75.88% |
| direct recall | 93.96% |

这里要强调：设备异常“有没有被发现”已经较强；anomaly 与 direct 的细粒度区分仍是不同难度的问题。

### 8.4 静态场景-响应后融合

当前静态融合汇总：

| 指标 | 结果 |
|---|---:|
| 场景共识 Macro-F1 | 0.9942 |
| 场景 Accuracy | 99.57% |
| 场景上下文覆盖率 | 99.86% |
| 联合诊断 recall | 90.76% |
| anomaly joint recall | 75.69% |
| direct joint recall | 93.53% |

解释时应指出：融合对 anomaly 的额外损失只有约 0.19 个百分点，对 direct 的额外损失约 0.43 个百分点；anomaly joint recall 较低主要来自 anomaly 状态自身较难区分，而不是场景分支失效。

### 8.5 动态场景结果

动态结果单独成节，至少报告 overall、static、dynamic 和 `dy_L5`。当前 mixed 基线中 `dy_L5` 是主要瓶颈，不能用 overall pooled 分数掩盖动态 L5 的困难。

## 9. 讨论与边界

### 9.1 学术意义

- AGC 不是简单的“无效特征”，而是可能在单设备内有效、跨设备时产生捷径学习的设备相关特征。
- 非目标频段的变化不应默认标记为直接欺骗；将其建模为关联异常能保留观测事实和设备差异。
- 频段聚合与设备状态分层使系统输出更接近真实部署需要：既知道攻击场景，也知道设备是否直接受骗或仅出现异常响应。

### 9.2 适用范围

- 主要面向广播式、多星同频、频段级民用欺骗。
- 对单星欺骗、选择性 PRN 欺骗和精细化空间选择攻击，场景分支只能判断频段级攻击存在，不能替代具体卫星定位。
- 设备状态 `anomaly` 是“攻击相关的可观测异常”，不是芯片内部机理已经被证明的结论。

### 9.3 不能作出的结论

- 不能说卫星级方法“没有用”；应说其在当前异构设备和 L5 场景下存在泛化瓶颈。
- 不能把 validation 高分直接当作泛化性能。
- 不能把不同任务的 recall 直接排序。
- 不能把已经反复读取的 outer test 数字包装为全新的独立盲测。

## 10. 结论与未来工作

结论建议围绕三点：

1. 消费级设备异构性会改变特征的跨设备可迁移性，去除或相对化硬件专属特征是提高泛化的关键。
2. L5 欺骗可能伴随非目标 L1 的设备关联异常，因此 direct 与 anomaly 需要分开表达。
3. 场景分支、设备响应分支和后融合能够形成一个轻量、可解释的联合诊断系统，但仍需在冻结协议下完成最终多折和动态验证。

未来工作：

- 完成 C/N0-only 与当前去 AGC 8 维版本在完全相同融合协议下的公平复验；
- 解决没有初始正常基线的 fold_3 协议问题；
- 提升 anomaly recall，尤其检查 RedMi、Huawei 和 Watch 的设备/场景差异；
- 补充动态多折和端侧推理开销；
- 引入更多设备和芯片，并探索设备条件化而非设备身份记忆；
- 进一步研究卫星级精细定位与频段级场景检测的联合输出。
