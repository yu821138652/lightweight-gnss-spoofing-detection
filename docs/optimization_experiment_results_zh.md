## 0. 当前阶段 3 的数据链路准备

严格按阶段顺序推进后，场景分支先进入特征优化，不立即进行 GRU/TCN 结构比较。
现有 `processed_gnss_data.csv` 为保持历史实验兼容只保留了伪距率不确定度，没有保留
原始 `PseudorangeRateMetersPerSecond`、`State` 和 ADR 字段，因此 S2--S5 不能仅通过训练参数切换完成。

已补充可选的数据链路，且不改变历史输出：

```text
04_build_labeled_processed_csv.py --include-dynamic-raw-features
    -> 保留伪距率、State、ADR 原始字段到新的 CSV
45_build_band_mean_window_tensors.py --include-pseudorange-rate
    -> 为每个频段构建 Prr 均值、因果斜率、稳健 MAD、异常比例
47_aggregate_band_mean_cv.py --include-pseudorange-rate
    -> 在固定 S1 协议下执行 S2 六折场景训练与汇总
```

本节新增代码只负责准备 S2，尚未产生 S2 性能结果。S1 仍使用原有四维
`L1_Cn0DbHz/L5_Cn0DbHz/L1Present/L5Present` 作为对照；S2 的训练必须使用
同一协议、同一 TCN 和相同六折，不能把新增特征与模型结构变化同时引入。

## 0.1 S2：加入伪距率动态特征

S2 在与 S1 完全相同的六折静态协议、窗口长度、TCN 结构和训练参数下，追加每个频段的
伪距率均值、因果斜率、稳健 MAD 和异常比例。六折 pooled 结果如下：

| 指标 | S1 C/N0-only | S2 C/N0 + 伪距率 | 变化 |
|---|---:|---:|---:|
| Macro-F1 | **0.9921** | 0.9312 | **-6.10 个百分点** |
| Accuracy | **0.9944** | 0.9377 | -5.67 个百分点 |
| normal recall | **99.89%** | 91.82% | -8.08 个百分点 |
| L1 recall | 98.46% | **98.33%** | -0.12 个百分点 |
| L5 recall | **98.24%** | 97.01% | -1.22 个百分点 |
| L1+L5 recall | **98.83%** | 98.66% | -0.17 个百分点 |
| L5 precision | **99.71%** | 71.92% | **-27.79 个百分点** |

S2 的主要错误是正常窗口被误判为 L5：六折 pooled 混淆矩阵中有 `1313` 个 normal
窗口预测为 L5，而 S1 只有 `10` 个。说明当前伪距率聚合特征在跨设备/跨 Session
条件下产生了明显的域偏移，模型把正常伪距率变化当成 L5 场景证据。S2 记为负结果，
不进入当前正式场景分支，也不通过继续调阈值来挽救。

## 0.2 S3：State/ADR 连续性特征（待运行）

S3 从 S1 四维 C/N0 输入重新开始，不叠加 S2 伪距率特征。新增特征为每个频段的：

- `StateCodeLockRatio`；
- `StateTowDecodedRatio`；
- `StateSwitchRatio`；
- `AdrResetSlipRatio`；
- `AdrStateSwitchRatio`；
- `AdrAbsDiffMedian`；
- `StateAdrMissingRatio`。

数据构建和六折汇总入口已经补齐，待运行后再判断 State/ADR 是否能提供 C/N0 之外的
稳定场景证据。

S3 六折 pooled 结果如下：

| 指标 | S1 C/N0-only | S2 C/N0 + 伪距率 | S3 C/N0 + State/ADR |
|---|---:|---:|---:|
| Macro-F1 | **0.9921** | 0.9312 | 0.9452 |
| Accuracy | **0.9944** | 0.9377 | 0.9643 |
| normal recall | 99.89% | 91.82% | **99.64%** |
| L1 recall | 98.46% | 98.33% | **98.04%** |
| L5 recall | **98.24%** | 97.01% | 94.00% |
| L1+L5 recall | **98.83%** | 98.66% | **77.49%** |

S3 的主要错误不是 S2 的正常到 L5 误报，而是 `L1+L5` 被判为 normal：共有 `583`
个双频攻击窗口落入 normal 类。State/ADR 特征没有提供稳定的双频场景证据，反而
破坏了原本由 C/N0-only 建立的双频判别边界。因此 S3 记为负结果，不进入当前正式
场景分支；下一步继续测试 S4 伪距残差特征。

## 0.3 S4：稳健伪距残差代理（待运行）

当前仓库没有卫星星历、PV 解算或接收机位置输入，因此无法构造严格的几何伪距残差。
S4 暂采用因果、同一历元内按星座分组的稳健残差代理：先以同历元同星座伪距中位数
作为参考，再按 L1/L5 聚合残差 MAD、P95 和异常比例。该特征不使用未来窗口，但不应
在论文中表述为完整 PV 残差；若结果无效，应将其作为数据条件限制记录。

S4 六折 pooled 结果如下：

| 指标 | S1 C/N0-only | S2 伪距率 | S3 State/ADR | S4 伪距残差代理 |
|---|---:|---:|---:|---:|
| Macro-F1 | **0.9921** | 0.9312 | 0.9452 | 0.9888 |
| Accuracy | **0.9944** | 0.9377 | 0.9643 | 0.9920 |
| normal recall | **99.89%** | 91.82% | 99.64% | 99.64% |
| L1 recall | **98.46%** | 98.33% | 98.04% | 98.37% |
| L5 recall | **98.24%** | 97.01% | 94.00% | 98.01% |
| L1+L5 recall | **98.83%** | 98.66% | 77.49% | 98.52% |

S4 相比 S1 的 Macro-F1 下降约 `0.33` 个百分点，四类 recall 均略低于 S1，但没有
出现 S2 的大规模正常→L5 误报或 S3 的双频场景塌陷。因此 S4 可作为接近基线的
补充消融，但当前正式场景分支仍优先选择输入更少、表现更好的 S1 四维方案。

## 0.4 S5：跨频段相对特征（待运行）

S5 不重新读取原始字段，直接在频段均值序列上加入：

- L1/L5 C/N0 斜率差；
- L5 上升且 L1 下降的联合指示；
- L1 上升且 L5 下降的联合指示。

这些特征用于检验此前观察到的“目标频段上升、非目标频段受压制下降”是否能帮助
区分 L1、L5 和 L1+L5 场景。S5 结果完成后，阶段 3 的特征消融即告一段落。

S5 六折 pooled 结果如下：

| Macro-F1 | **0.9921** | 0.9312 | 0.9452 | 0.9888 | 0.9637 |
| Accuracy | **0.9944** | 0.9377 | 0.9643 | 0.9920 | 0.9745 |
| normal recall | 99.89% | 91.82% | 99.64% | 99.64% | **99.83%** |
| L1 recall | 98.46% | 98.33% | 98.04% | 98.37% | 98.17% |
| L5 recall | **98.24%** | 97.01% | 94.00% | 98.01% | **86.25%** |

S5 的主要错误是 `L5` 被判为 normal，共 `483` 个窗口；另有 `106` 个 `L1+L5`

### 阶段 3 特征选择结论

阶段 3 的六折对照已经完成：

1. **正式场景特征候选：S1 四维 C/N0-only**；
2. S4 伪距残差代理性能接近 S1，但增加特征和计算复杂度，暂不采用；
3. S2 伪距率、S3 State/ADR、S5 跨频段相对特征均为负结果；
4. 后续阶段 4 的所有模型比较固定使用 S1 四维输入，不能再同时改变特征集合。

### 2.4 结论

R1 不能直接替代 O0，原因是：

1. FAR 明显下降，说明去掉设备身份后模型的误报更少；
2. direct recall 小幅提高，RedMi K60 也有改善；
3. 但 abnormal recall 和 anomaly recall 明显下降，Pixel6、Watch1 和 MI8 受到较大影响；
4. Macro-F1 的提升主要来自 FAR/precision 改善，不能解释为整体异常检测能力提升。

因此，设备 one-hot 不是简单的“无用设备捷径”。在当前特征设计下，它承担了一部分设备条件化作用，但也牺牲了跨设备泛化的风险。R1 的正确定位是：

> 一个低误报、较保守的无设备身份对照版本，而不是当前最终响应模型。

### 2.5 后续决策

不立即把 R1 扩展到全部六个 fold，先继续做两个更有解释力的变体：

1. **R2：去掉跨频段差值和耦合特征**，判断 anomaly 识别是否主要依赖这些特征；
2. **R3/R4：设备能力掩码版本**，保留“是否有 L5/AGC”等可解释能力信息，但不直接输入设备身份 one-hot。

如果能力掩码能够恢复 R1 丢失的 abnormal/anomaly recall，同时保持较低 FAR，就优先采用“能力条件化”而不是“设备身份条件化”。

- direct recall 也没有提升。

能力掩码虽然比设备 one-hot 更抽象，但在当前训练/测试设备和 Session 分布下仍然形成了不稳定的设备条件捷径。它不能作为当前响应分支的改进方向，R3 记为负结果并停止扩展。

当前响应分支候选仍为 R2：`initial_baseline_delta_no_cross + MLP-h32`。

下一步转向**模型规模消融**：固定 R2 特征，比较 MLP hidden=8、16、32 以及线性模型，寻找更小而性能不明显下降的模型。

## 6. 模型规模实验：R2 + Linear

### 6.1 Fold 6 结果

R2 特征维度为 81。线性模型约有 246 个三分类参数和 164 个 direct expert 参数，权重文件约 2.4 KB；R2 的 MLP-h32 checkpoint 约 12.9 KB。

| 指标 | R2 + MLP-h32 | R2 + Linear |
|---|---:|---:|
| Macro-F1 | **0.8760** | 0.7952 |
| FAR | **1.45%** | 3.72% |
| abnormal recall | **91.78%** | 81.01% |
| anomaly recall | 98.26% | **98.52%** |
| direct recall | **68.59%** | 48.43% |
| direct threshold | 0.1 | 0.5 |
| 模型权重大小 | 约 12.9 KB | **约 2.4 KB** |

### 6.2 结论

线性模型虽然保留了 anomaly recall，但 direct recall 下降约 20 个百分点，abnormal recall 下降约 11 个百分点，且 FAR 上升。因此当前设备响应任务需要一定的非线性建模能力，不能直接用线性模型替代 MLP。

线性模型仍可作为轻量化下界对照；下一步继续测试 MLP hidden=16，再根据性能损失判断是否可以从 hidden=32 压缩到更小模型。

## 7. 模型规模实验：R2 + MLP-h16

### 7.1 Fold 6 结果

| 指标 | R2 + Linear | R2 + MLP-h16 | R2 + MLP-h32 |
|---|---:|---:|---:|
| Macro-F1 | 0.7952 | **0.8765** | 0.8760 |
| FAR | 3.72% | **0.89%** | 1.45% |
| abnormal recall | 81.01% | 89.07% | **91.78%** |
| anomaly recall | 98.52% | 98.59% | 98.26% |
| direct recall | 48.43% | 66.64% | **68.59%** |
| direct threshold | 0.5 | 0.1 | 0.1 |
| base checkpoint | 约 2.4 KB | **约 7.5 KB** | 约 12.9 KB |
| direct checkpoint | 约 2.4 KB | **约 7.4 KB** | 约 12.9 KB |

### 7.2 结论

MLP-h16 已恢复大部分非线性建模能力，在 Fold 6 上 Macro-F1 略高于 h32，FAR 更低，模型权重约为 h32 的 58%。但 abnormal recall 和 direct recall 分别低约 2.7 和 1.9 个百分点。

因此当前存在一个明确的轻量化权衡：

- 若优先低误报和模型大小，MLP-h16 更有吸引力；
- 若优先整体异常发现和 direct recall，MLP-h32 更稳妥；
- 不能只按 Macro-F1 选择，应在其余有效 fold 上比较最差设备 recall 和 TTD。

### 8.1 Fold 6 结果

|---|---:|---:|---:|
| Macro-F1 | 0.8656 | **0.8765** | 0.8760 |
| FAR | 3.18% | **0.89%** | 1.45% |

| direct recall | 66.95% | 66.64% | **68.59%** |
| direct threshold | 0.4 | 0.1 | 0.1 |

### 8.2 结论

MLP-h8 虽然参数和权重最小，但 FAR 明显高于 h16，Macro-F1 也下降。因此 h8 暂不作为主要候选。

当前模型规模候选收敛为：

- **MLP-h16**：轻量化优先候选，权重约 7.5 KB；
- **MLP-h32**：性能优先候选，abnormal/direct recall 更高。

下一步不再继续在 Fold 6 上试更多 hidden size，而是将 h16 和 h32 扩展到其余有效 fold，比较跨 Session、逐设备和 TTD 的稳定性。

## 9. 响应分支 CPU 前向资源对比

测量脚本：`pipeline_total/53_measure_response_runtime.py`。以下是在同一 CPU、单线程、已加载模型和已构建张量上的纯模型前向测量，不包含 CSV 解析、设备特征聚合、阈值校准和场景后融合。

| 分支 | 模型 | 参数量 | 权重大小 | 单窗口 p50 | 单窗口 p95 | batch 吞吐 |
|---|---|---:|---:|---:|---:|---:|
| base | MLP-h16 | 1,363 | 7.5 KB | 0.0366 ms | 0.0532 ms | 3.67M windows/s |
| base | MLP-h32 | 2,723 | 12.9 KB | 0.0363 ms | 0.0588 ms | 3.14M windows/s |
| direct expert | MLP-h16 | 1,346 | 7.4 KB | 0.0373 ms | 0.0848 ms | 3.95M windows/s |
| direct expert | MLP-h32 | 2,690 | 12.8 KB | 0.0347 ms | 0.0366 ms | 3.30M windows/s |

当前结论：h16 的参数量和权重大小约为 h32 的一半，批量吞吐也更高；单窗口延迟受 Python/PyTorch 调度开销影响，h16 与 h32 差异很小。因此 h16 的轻量化优势主要体现在模型存储、批量吞吐和参数量，而不是单次前向延迟数量级下降。

该表不能替代端到端部署测量，后续仍需加入特征构建、场景分支、后融合和设备实际 CPU 环境的完整延迟。
