# 隔壁组论文分析：CWT-ConvNeXt 欺骗检测模型

> 分析对象：`tmp/中文论文最终版.pdf`
> 定位：隔壁组的工作，任务目标与我方接近，使用基本相同的数据集，但技术路线与设置差异很大。
> 本文档汇总我方对该论文的完整评估，用于（1）明确我方差异化定位，（2）为我方论文的 Related Work / 实验讨论提供素材，（3）预判审稿人可能的质疑点。

---

## 一、他们的技术路线

一句话概括：**把欺骗检测从"时序分类"改造成了"图像识别"**。

流程：

```
一维观测量 (Cn0DbHz, AgcDb, delta_cnr)
  → 滑动窗切分 (窗长 224, 步长 50)
  → CWT 连续小波变换
  → 224×224 二维时频图 (3 通道)
  → ConvNeXt-Tiny 分类
```

核心叙事是 **"硬件指纹"**：同一场欺骗攻击，不同设备因芯片/天线差异，在 AGC、C/N0 上体现出的数值基线、动态范围、噪声形态完全不同（论文用 Fig 6–15 一堆图论证）。他们的假设是：CWT 时频图里的**纹理**是跨设备普适的攻击"图案"，而具体数值是设备指纹；用足够强的 CNN 骨干去学纹理、忽略绝对数值，就能跨设备泛化。

### 特征与预处理（论文第 6 页，明确给出）

- **三个输入通道**：Cn0DbHz（C/N0）、AgcDb（AGC）、delta_cnr（C/N0 一阶差分）。
- **标准化**：只对 AgcDb 做逐文件 Z-score（`x' = (x−μ)/σ`），称之为"消除硬件指纹第一步"；C/N0 保留原值。
- **窗口切分**：窗长 **224 时间点**，步长 **50 时间点**，相邻窗重叠 **174/224 ≈ 77.7%**。每个窗构成一个 `[224 × 3]` 原始样本，再经 CWT 变成 224×224 时频图。
- 他们给的重叠理由：保证欺骗瞬态无论落在数据流哪个位置都能被至少一个窗完整捕捉。

### 模型（论文第 6–7 页）

- 骨干 ConvNeXt-Tiny（约 28M 参数）。词干层 4×4 步长卷积，通道扩到 96；四个 Stage（3/3/9/3 块）；全局平均池化 + LayerNorm + 线性分类器。
- 训练：AdamW，初始 lr=1e-4，余弦退火 + 火热衰减；正则用 DropPath (0.1) 与 LayerScale (1e-6)。

## 二、与我方路线的差异

| 维度 | 他们 | 我们 |
|---|---|---|
| 问题建模 | 时序 → 图像识别 | 时序 / 表格分类 |
| 特征 | Cn0DbHz + AgcDb + delta_cnr 三通道做 CWT | 挖原始 Android 日志更多字段（ADR / 时钟 / 伪距率等） |
| 骨干 | CWT 预处理 + ConvNeXt-Tiny (28M) | 轻量化模型 |
| 样本粒度 | ~3.9 万个样本（每个 = 一张 CWT 图 / 一个窗） | 267 万条（逐历元 / 逐测量判定） |
| 目标 | 纯精度；轻量化仅"顺带一提" | 精度 + 轻量化并重 |

**最本质差异是样本粒度**：他们混淆矩阵总量 **39239**（TN 20843 + FP 1856 + FN 1643 + TP 14897），我方这版是 **2,677,304 条**，相差约 68 倍。原因见第四节。**两套数字不能直接比大小**，这是后续所有比较的前提。

## 三、他们"闭口不谈"或存在硬伤的问题

1. **轻量化基本是空话。** 号称 ConvNeXt-Tiny "非常轻量化、适合边缘部署"，但：
   - 28M 参数在移动端不算轻；
   - 更关键，**每次推理前要先做 CWT**——连续小波变换是计算密集操作，时频图额外占内存。CWT + 28M CNN 的组合在手表/手机上的实时性与功耗很难看；
   - 全文**没有任何 FLOPs、延迟、内存、功耗数据**，一句"巨大潜力"带过。→ **我方可正面碾压的点。**

2. **跨设备泛化没有严格比较。** 声称做了"留一设备交叉验证"，但表 II 只给 5 模型的**宏平均**，**没有任何逐设备结果表**。哪台设备泛化差、差多少完全看不到。很可能同样藏着某台设备/某类场景的塌陷（对照我方 `dy_L5` 场景 Recall 仅约 22% 的教训）。

3. **混淆矩阵归属自相矛盾。** 正文说"Fig 13 以 HUAWEI 设备为例"，紧跟的混淆矩阵却给出 Acc 0.9108 / F1 0.8949，**与表 II 中号称 5 轮宏平均的 "Ours" 行一字不差**。单台设备结果不可能恰好等于跨设备宏平均。要么矩阵实为聚合结果被错标为 HUAWEI，要么数据拼接有问题——审稿人会抓的硬伤。

4. **图注编号错乱。** 正文 Fig 6–10 讲 AgcDb，图注却写成 Cn0DbHz；Fig 12 同时是"雷达图"又被 Fig 13 复用。制作粗糙。

5. **"覆盖十余种主流品牌"夸大。** 结论这么写，但表 I 只有 **5 台**设备。

6. **高指标主要靠单一特征。** 由 Fig 2/3 相关性：真正扛事的只有 Cn0DbHz（Pearson 0.50）；delta_cnr 只有 0.04，AgcDb 为 −0.12。三通道里两个几乎不相关，说明高指标主要靠 C/N0 一个量在撑，"三维度信息互补增强鲁棒性"的叙事缺乏相关性数据支撑。

7. **标准化与主张矛盾。** 只对 AgcDb 做 Z-score，C/N0 保留原值。但 C/N0 的绝对基线恰是最强的设备指纹之一，却没被归一化，与"消除硬件指纹"主张相悖。

## 四、样本总量为什么少、窗口怎么分（已由论文第 6 页确认）

- **窗长 224、步长 50**：每前进 50 个历元才产出一个窗 → 窗数 ≈ 总历元 / 50，天然比逐历元判定少约 50 倍。这是 3.9 万 vs 267 万的机制来源。**决定倍率的是步长 50，不是窗长。**
- **留一设备交叉验证**：5 台设备各被当一次测试集，5 轮测试样本汇总正好等于整个数据集。故 **39239 ≈ 他们整个数据集的 CWT 图总数**（5 台合计），平均每台约 7800 张图。样本量对深度模型偏小，也是不敢拆逐设备结果的潜在原因（单台方差大）。
- **一个对不上的小账**：若两边底层同源，267 万 / 50 ≈ 53500 个窗才对，他们只有 39239，差约 27%。很可能来自**数据清洗 / 抽稀**（论文未交代）或两边原始总时长不同。缺口悬而未决。

### 由此放大的泄漏风险

- **77.7% 重叠意味着相邻窗几乎是同一段数据。** 只要划分里出现随机切分，相邻高相关窗会一半进训练一半进测试，指标被显著抬高。
- 他们的**留一设备验证对此是安全的**（整台设备被留出，同设备重叠窗不跨训练/测试边界）——须如实承认，不能硬扣。
- **风险在别处**：表 II 那个混淆矩阵前面说是"以 HUAWEI 为例"，数字又与宏平均一致。若该矩阵实为**单设备内部含重叠窗的随机划分**结果，则 91% 含泄漏水分；叠加 77.7% 重叠，此疑点更硬。

## 五、结果对比

先补出他们没明说的 **FAR**：FAR = FP/(FP+TN) = 1856/22699 = **8.18%**（= 1 − Specificity 0.9182，自洽）。

| 指标 | 他们 | 我方这版 | 点评 |
|---|---|---|---|
| Accuracy | 91.08% | 89.85% | 他们略高 1.2 点，但样本粒度不同，含金量不可比 |
| FAR（误报率） | **8.18%** | **4.00%** | **我方显著更好，他们误报率是我方两倍** |
| Precision | 88.92% | 87.68% | 基本持平 |
| F1 | 0.8949（**欺骗类二分类 F1**） | 86.68%（**Macro-F1**） | **口径不同，不能直接比** |
| Recall | 90.07% | 73.88% | 表面他们高，但见下 |

两个必须点破的陷阱：

- **F1 口径不一致。** 他们的 0.8949 是欺骗类二分类 F1；我方 86.68% 是 Macro-F1（要两类都好，天然更苛刻）。拿他们的二分类 F1 压我方 Macro-F1 不公平。**要比就统一：让他们也报 Macro-F1，或我方也报二分类 F1。**
- **Recall 高但 FAR 也高，只是操作点不同。** 他们 Recall 90% / FAR 8.18%，我方 Recall 73.88% / FAR 4%。他们阈值更激进（宁误报也抓全），我方更保守（宁漏不误报）。这是 ROC 曲线上不同工作点，不是能力差距。**公平比较应画 ROC/PR 看 AUC，或在同一 FAR 下比 Recall。** 且他们那 90% 是 3.9 万样本上、不拆场景的，很可能同样藏着某类场景的低 Recall。

## 六、我方定位与打法（按优先级）

**他们的价值**：提出了"硬件指纹 → CWT 消除"的漂亮叙事，以及一个跨设备数据集。story 本身讲得比数字更好。

**我方能打、他们绕不开的点**：

1. **轻量化是他们的真空区**——给出 FLOPs / 参数量 / 单次推理延迟 / 内存的硬数字，强调 CWT + ConvNeXt 在边缘端跑不起来。差异化最强一击。
2. **误报率我方客观更低（4% vs 8.18%）**——在"不打扰用户"这一消费级真正在意的指标上取胜。
3. **要求公平比较口径**：统一 F1 定义、给逐设备/逐场景拆分、画 ROC 在同 FAR 下比 Recall。一旦拆场景，他们藏起来的短板很可能暴露。
4. **诚实反而是优势**——我方已认清"迭代式 CV ≠ 真盲测"、也敢报 `dy_L5` 的 22%；他们连宏平均都不敢拆。审稿人越挖，他们越危险。

**须自我防守的点**：267 万 vs 3.9 万的粒度差异是双刃剑——粒度细使数字更可信，但也可能被质疑"时间上强相关的样本泄漏（同一窗/相邻历元既进训练又进测试）"。我方要先站稳这点，避免被反将一军。
