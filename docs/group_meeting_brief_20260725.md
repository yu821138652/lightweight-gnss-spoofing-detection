# 历史组会汇报底稿：静态逐 signal 欺骗检测（2026-07-25）

> 用途：2026-07-25 组会汇报的事实底稿、PPT 提纲和讨论问题。
> 本文保留当日的分析脉络，不是当前训练方案。2026-07-27 后的状态、结果边界与问题陈述以 `docs/handoff_status.md` 和 `docs/static_signal_fold6_diagnostics_20260727.md` 为准。

## 一页结论

本周没有得到能够显著解决操场 L5 的新模型，但完成了系统的排除性实验，并把问题收敛为两个可检验的工作假设：

1. **频段条件不对称与样本/梯度失衡。** L5-only 欺骗时，少量 L5 信号标为正类并常呈上升；同时大量 L1 信号可能受压制而下降，却按当前“目标频段欺骗”语义标为负类。共享模型需要同时学习频段条件化的相反模式，但训练损失并未显式平衡 `频段 × 类别`。
2. **设备相关 AGC 模式（共模偏移假设）。** Huawei 的 AGC 共模振荡可能被逐信号模型用作多颗卫星共享的欺骗证据，造成大量误报；但直接删除或相对化 AGC 又会牺牲 Huawei L5 的真实检出。

因此，当日的证据指向**任务定义、频段条件和设备域偏移**，而不是 TCN/LSTM 的容量不够。后续 E9-E11 诊断未改变“当前没有最终模型”的结论；其结果和边界已独立固化在 Fold 6 诊断快照中。

## 1. 当前可保留基线

### 任务与协议

- 仅使用 `LabelStatus=reviewed` 的静态 `st_*` 数据；动态数据未进入本轮主实验。
- 7 个完整静态 Session 采用 leave-one-session-out outer test；其余 Session 按连续 UTC 时间块作 inner train/validation。
- 每个样本为一个 `signal_id` 的 W5 因果窗口，标签为末端历元。窗口不跨 split、4 历元 guard 或超过 2 秒的来源断档。
- 连续特征仅由训练块拟合、按设备标准化；分类阈值固定为 0.5。

### 当前保留配置

`compact11 + TCN16 + dropout=.1`

- Raw TCN：`Cn0DbHz`、`AgcDb`、`ReceivedSvTimeUncertaintyNanos`、`PseudorangeRateUncertaintyMetersPerSecond`、`FreqBand`。
- stats MLP：C/N0 四统计、AGC 四统计、接收机时间不确定度 Std、`SignalHistoryRatioW5`、`AgcObservedRatioW5`，共 11 维。
- 不输入 CSV 中既有的 `Cn0DbHz_dt`、`Cn0DbHz_std`。
- TCN hidden=16、dropout=.1、1,880 参数；AdamW `lr=1e-3`、weight decay=`1e-3`、class-balanced CE、最多 30 epochs、patience=6。
- 完整输出：`output/training/static_timeblock_outer_v2_explore_compact11_tcn16_d10/`。

操场长 L5 的设备×频段诊断：

| 组别 | 主要错误 |
|---|---|

## 3. 本周已做的排除性实验

| 方向 | 代表结果（操场 L5 / fold 6） | 结论 |
|---|---|---|
| 当前 compact11 TCN16 d=.1 | F1 .6761，Recall 55.86%，FAR 12.74% | 当前完整 7-fold 保留基线 |
| TCN32 | F1 .6596；参数从 1,880 增至 6,296 | 增大容量无益 |
| LSTM/GRU | LSTM 虽可提高部分 Recall，但 FAR 更高；GRU 更低 | 结构替换无同时改善 |
| 窗口 W3/W5 pilot | .6226 / .5847（筛查协议为 `time_steps=7 / guard=6`，非主协议 W5 / guard=4） | 不能作严格横比；未呈现值得继续窗口搜索的正向证据 |
| 普通 stats 消融 | 无一项在难例取得可推广改善 | 不能靠简单删特征解决 |
| 删 raw + stats AGC | F1 .6998，Huawei L1 FAR 14.82%；Huawei L5 Recall 54.78% | 误报下降以真实检出为代价，跨折不稳定 |
| AGC 同刻同频段中位数残差 | F1 .6889，Huawei L1 FAR 8.98%；Huawei L5 Recall 53.69% | 支持模型对设备相关共模 AGC 模式敏感，但不是最终方案 |

这些负结果是有价值的：它们排除了“继续堆容量”“只换窗口”“直接删 AGC”等低成本但不可行的方向。

## 4. 工作假设：为什么 L5-only 特别困难

### 可观察事实

1. 当前标签语义是“目标时间区间内且 `FreqBand==5` 才为正类”。因此 L5-only 欺骗期间的 L1 信号按当前定义仍为负类。
2. 特征图中，L1-only 场景通常有较多 L1 信号上升；L5-only 场景中，上升的 L5 信号较少，而较多 L1 信号可能下降，表现为受压制/受干扰。
3. 当前模型已经接收 `FreqBand`，因此“是否把 L1/L5 告诉模型”并不是尚未尝试的变量；问题更可能是共享表征和全局损失无法充分学习频段条件化的少数 L5 正类。
4. `no_IsL5` 虽在 Session 等权平均上略高，但操场 L5 降至 0.6119；仅改变频段标记并不能解决问题。

### 尚待验证的解释

> 在 L5-only 欺骗中，大量 L1 负类和少量 L5 正类同时出现。若 L1 下降代表真实的伴随压制，当前“二分类、逐信号、全局类别加权”的目标会把它作为大量负类梯度；少数 L5 的上升欺骗模式难以获得足够稳定的频段条件化表征。这可能是 Redmi L5 漏检的重要原因，但还需要频段平衡训练实验证实。

这不是直接证明“L1 标签打错了”。L1 下降可能是正常/受压制/受干扰的真实响应；其应当被标为负类、忽略样本、还是第三类“干扰”，需要结合采集事实与老师意见决定。

## 5. 当时拟向老师确认的问题（历史记录）

1. **标签语义：** L5 欺骗期间，受压制的 L1 信号应保持正常负类，还是应标为不确定并从训练损失中忽略？是否需要把“干扰”作为独立第三类？
2. **真实参考：** 隔壁组是否保留了设备开启、频段配置、功率或时间边界的更可靠记录，可用于确认 L1 下降究竟是伴随压制还是标注边界问题？
3. **研究主任务：** 论文是否继续以卫星/`signal_id` 检测为主，将设备级告警只作为后处理？这会决定标签和评价单位。
4. **下一步实验授权：** 是否同意先做频段条件化损失/双头模型，而不是继续搜索更复杂的时序网络？

## 7. 5 页 PPT 建议

1. **问题与当前结论：** 7-fold 总体结果可用，但操场 L5 仍失败；本周没有更高分模型，却完成了问题定位。
2. **已完成的对照实验：** 模型、窗口、AGC、特征消融一张表，展示为何停止常规调参。
3. **L1/L5 特征图与标签语义：** 并排放 L1-only、L5-only、L1+L5 的 label plots；标出“L5 少量上升正类 + L1 大量下降负类”。
4. **设备×频段错误结构：** Huawei L1 误报、Huawei L5 误报、RedMi L5 漏报三项柱状图或表格。
5. **工作假设、待确认问题和结果边界：** 说明标签语义、采集真值和独立测试数据仍需确认，不将单一折次结果表述为最终模型。

## 9. 汇报时的表述边界

- 应说“发现了有证据支持的机制假设”，不要说“已经证明标签全部错了”。
- 应说“AGC 是 Huawei 误报的重要捷径”，不要说“AGC 完全无用”。
- 应说“当前结果是迭代式交叉验证开发结果”，不要说“最终独立测试精度”。
